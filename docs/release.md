# 首次发布

## 在线体验构建

用户于 2026-11-11 要求通过 GitHub.io 体验后反馈。单独的 `experience` 构建可先发布为明确标识的开发预览，使用少量原创样题，不连接题源、不消耗源站额度，不作为整册真实内容发布。真实取题后台继续暂停。

运行 `npm run build:experience`，静态文件输出到被忽略的 `.tools/pages-experience/`。将这一目录与 `.nojekyll` 发布到 `codex/pages-experience` 分支，再将 Pages 来源设置为该分支根目录；入口为 `https://mutiwangn.github.io/quiz/`。该分支只存放构建产物，代码仍在 `codex/build-quiz` 草稿 PR 中。

普通 `npm run build` 仍是正式构建，不包含开发样题；网址中的 `?preview=1` 不能开启正式构建的样题模式。首次正式实时版发布仍须满足以下全部条件，并切换到经过覆盖检查的 Pages Actions 工作流。

## 必要条件

1. 接口免费访问或试用权限明确；确认教科版（2024）四上课时筛选、完整题干、答案、图片可用范围与额度。
   页面提取路径须先验证完整正文可读。列表有非零题号、答案标记或 HTTP 200 都不能单独证明题干完整；查看完整详情可能消耗免费次数，先小样本验证和核对额度，再运行整册检查。
2. 完成真实接口适配，部署后台，密钥仅在服务端。
3. 真实运行 `npm run coverage:live`，24 课时 × 两类题型均通过。
4. 电脑和 iPad 真机完成选课、取题、配图、单人与双人流程；大陆课堂网络可达。
5. 在 GitHub 仓库变量中配置公开的 `QUIZ_API_URL`，将 Pages Source 设为 GitHub Actions，手动运行 `Publish whole-book Quiz`。

Pages 工作流只接受手动触发，实时覆盖不通过则不会构建或部署。仓库的 `main` 分支不会因为普通推送就发布内容不完整的网站。

## 覆盖检查

```powershell
$env:QUIZ_API_URL = 'https://your-quiz-api.example'
npm run coverage:live
```

报告写入 `coverage/live-coverage.json`。每课时每题型检查 5 道不同题，共 48 项；这是可用性抽样证据，不代表题源全部题目都已经审校，也不保证每课时一定支持 30 题。数量不足时开局明确失败，不重复填满。内容变化后可以再次运行。

全局权限缺失、未配置或配额耗尽时，检查首项失败后停止实际请求；其余课时标记 `not-run`，不把没有尝试的请求记成已验证失败。`publishable` 只有在 48 项全部通过后才为 `true`。

遇到本服务的 `RATE_LIMITED`，程序按 `Retry-After` 等待并重试当前课时，最多重试两次；等待时输出进度。上游免费总额度耗尽则停止检查，不通过重试继续消耗配额。

本地测试只能证明对局和接口契约行为，不能替代上述真实内容验收。iPad 尺寸与触控仿真不能替代 Safari 真机试用。源数据不具备明确标准答案时不自动生成答案。
